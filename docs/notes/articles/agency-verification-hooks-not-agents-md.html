Джеффри Хантли — автор известной в кругах «агентного кодинга» техники Ralph (простой цикл, в котором агент перезапускается с нуля, а память переносится через файлы на диске) и один из авторов термина «loop engineering». Разобранное здесь эссе — сопроводительный пост к разговору с Джошем Вулфом на подкасте Agentic Engineering; его заголовок прямо формулирует тезис: раз написание кода руками больше не узкое место, единственное, что остаётся инженеру-человеку, — это то, что нельзя делегировать агенту целиком. Geoffrey Huntley is known in agentic-coding circles for Ralph — a deliberately simple loop where the agent restarts from scratch each time and memory is carried only through files on disk — and is one of the people credited with the term "loop engineering." The essay digested here is a companion post to a conversation with Josh Wulf on the Agentic Engineering podcast; its title states the thesis directly: once typing code by hand stops being the bottleneck, whatever is left for a human engineer is whatever can't simply be handed to an agent.

Приём: не инструкция, а хук, который проверяет и чинит The technique: not an instruction file, but a hook that checks and corrects

Единственный подтверждённый дословной цитатой фрагмент эссе описывает конкретную проблему и её решение. Проблема: файл с инструкциями для агента (AGENTS.md) должен описывать принятые в проекте соглашения — например, что весь код обязан идти через собственный модуль диагностики, а не обращаться к модулям логирования/мониторинга напрямую, — но по мере того как агент пишет всё больше кода, такой файл неизбежно расходится с реальностью: его можно подправить вручную, но разрыв («delta») всё равно будет накапливаться и «дрейфовать». Решение, которое приводит Хантли: вместо того чтобы полагаться на статичный файл инструкций, он пишет pre-commit хук, который проверяет git diff на прямые обращения к модулям логирования в обход диагностического модуля. Если хук находит нарушение, коммит проваливается, а агенту тут же возвращается промпт с указанием использовать диагностический модуль вместо прямого вызова. По словам автора, после этого соблюдение соглашения выросло до «десять из десяти» — то есть из разового пожелания в файле инструкций правило превращается в механическую проверку, которую нельзя обойти молча. The one part of the essay confirmed by a verbatim quote describes a specific problem and its fix. The problem: an agent instructions file (AGENTS.md) is supposed to encode a project's conventions — for instance, that all code must go through an in-house diagnostics module rather than calling logging/observability modules directly — but as an agent writes more and more code, that file inevitably drifts out of sync with reality; you can patch it by hand, but the gap ("delta") keeps accumulating. Huntley's fix: instead of relying on a static instructions file, he writes a pre-commit hook that inspects the git diff for direct calls to observability modules that bypass the diagnostics module. When the hook finds a violation, it fails the commit and immediately feeds a prompt back to the agent telling it to use the diagnostics module instead. By his account, compliance then went to "ten out of ten" — turning a one-off wish stated in an instructions file into a mechanical check that can't be silently skipped.

Ограничение, которое следует из самой формы приёма (а не домыслено отдельно): он имеет смысл там, где объём и темп написанного агентом кода уже сделали ручной контроль соглашений нежизнеспособным, и требует, чтобы сама проверка (хук, тест) могла быть выражена как механическое правило, а не как смысловое суждение, — то есть годится не для любых соглашений, а для тех, что можно формально детектировать по диффу. The limitation follows directly from the shape of the technique itself (not inferred separately): it only makes sense once the volume and pace of agent-written code have already made manual convention-checking unworkable, and it requires the check itself (a hook, a test) to be expressible as a mechanical rule rather than a judgment call — so it fits conventions that can be formally detected from a diff, not arbitrary ones.
