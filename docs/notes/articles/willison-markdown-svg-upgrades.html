Обновления markdown-svg-renderer: удобный способ делиться SVG, которые рисуют LLM Markdown SVG upgrades: a better way to share SVGs that LLMs draw

Оригинал заметки ↗Original post ↗

Саймон Уиллисон рассказывает об очередном витке доработок своего инструмента markdown-svg-renderer, который он начал делать ещё в мае и с тех пор регулярно расширяет. Задача инструмента простая и узкая, но у самого Уиллисона — регулярная: он постоянно тестирует модели своим фирменным запросом «нарисуй пеликана на велосипеде в формате SVG» и ему нужен удобный способ показывать читателям результат — Markdown-текст с embedded SVG-кодом внутри, который браузер сам по себе не отрендерит. Simon Willison writes about another round of improvements to his markdown-svg-renderer tool, which he started building back in May and has kept extending since. The tool solves a narrow but, for Willison, recurring problem: he regularly benchmarks models with his signature "draw a pelican riding a bicycle in SVG" prompt, and needs an easy way to show readers the result — a Markdown document with raw SVG code embedded in it, which a browser won't render on its own.

Как это работаетHow it works

Инструмент устроен просто: на странице markdown-svg-renderer можно вставить Markdown-текст напрямую в браузере, либо сохранить его по CORS-совместимому URL или в GitHub Gist и передать инструменту только ссылку. Второй вариант даёт закладку-URL вида markdown-svg-renderer#url=..., в которую «запечён» адрес исходного документа, — такую ссылку удобно один раз сгенерировать и потом просто пересылать. Сырой SVG-код внутри исходного документа инструмент превращает в блок с несколькими вкладками, а не просто в статичную картинку. The tool itself is simple: on the markdown-svg-renderer page you can paste Markdown directly in the browser, or save it to a CORS-friendly URL or a GitHub Gist and hand the tool just the link. The second option produces a bookmarkable URL of the form markdown-svg-renderer#url=..., with the source document's address baked into it — generate it once and just forward the link from then on. The raw SVG code inside the source document gets turned into a multi-tab block, not just a static image.

Новое: экспорт анимированного SVG в MP4 прямо в браузереWhat's new: exporting animated SVG to MP4, right in the browser

До этого обновления инструмент уже умел показывать рендер SVG рядом с исходным кодом и отдавать его в виде PNG или JPEG — это полезно для площадок, которые не поддерживают вставку SVG напрямую. Главное новое в этой заметке — вкладка MP4: инструмент анализирует SVG на наличие анимации, сам оценивает разумную длительность зацикленного видео, рендерит по кадрам всю анимацию и подгружает в браузер библиотеку ffmpeg.wasm (около 30 МБ) — полноценный FFmpeg, скомпилированный в WebAssembly, — чтобы собрать эти кадры в MP4-видео, не отправляя ничего на сервер. Before this update, the tool could already show the rendered SVG next to the source code and export it as PNG or JPEG — useful for platforms that don't support embedding SVG directly. The main new thing in this post is the MP4 tab: the tool inspects the SVG for animation, estimates a sensible loop duration itself, renders the animation out frame by frame, and loads ffmpeg.wasm (about 30MB) into the browser — a full build of FFmpeg compiled to WebAssembly — to compile those frames into an MP4 video without sending anything to a server.

Зачем это нужноWhy it's useful

Практическая причина проста: многие площадки, где Уиллисон и другие делятся результатами тестирования моделей (соцсети, форумы, некоторые CMS), либо вообще не поддерживают SVG, либо не поддерживают именно анимированный SVG. Возможность одним кликом получить MP4-версию той же анимации снимает эту проблему — не нужно вручную записывать экран или искать отдельный конвертер. Это не переворот в подходах к использованию LLM, а скорее пример того, как небольшой самодельный инструмент вокруг регулярного бенчмарка модели постепенно обрастает практичными фичами, снижающими трение при демонстрации результатов. The practical reason is simple: many of the places Willison and others share model-benchmarking results (social platforms, forums, some CMSes) either don't support SVG at all, or don't support animated SVG specifically. Getting an MP4 version of the same animation in one click removes that friction — no need to manually screen-record or hunt for a separate converter. It's not a shift in how people use LLMs, more an example of how a small homegrown tool built around a recurring model benchmark gradually accumulates practical features that lower the friction of showing results.
