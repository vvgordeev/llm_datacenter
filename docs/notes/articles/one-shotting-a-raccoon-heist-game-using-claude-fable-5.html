Игра «Ограбление енотов» с одного промпта: Willison тестирует Claude Fable 5 без права на уточняющие вопросы One-shotting a Raccoon Heist game: Willison lets Claude Fable 5 build it with zero follow-up questions

Оригинал статьи ↗Original article ↗

Ровно четыре года назад Willison твитнул скриншоты игровой концепции «Raccoon Heist» («Ограбление енотов»), сгенерированной GPT-3 (текст) и DALL-E (арт). В этот раз он решил проверить, сможет ли Claude Fable 5 — запущенный в Claude Code for web — построить по мотивам того же твита полноценную играбельную игру, получив единственный первоначальный промпт и не имея права задавать уточняющие вопросы. Результат: рабочая 3D-игра на Three.js, доступная в браузере и на мобильном, с процедурной музыкой, генерируемыми текстурами и пусть примитивным, но честно работающим игровым циклом. Exactly four years earlier, Willison had tweeted screenshots of a "Raccoon Heist" game concept generated by GPT-3 (text) and DALL-E (art). This time he tested whether Claude Fable 5 — running inside Claude Code for web — could build a fully playable game from that same tweet, given one upfront prompt and no chance to ask clarifying questions. The result: a working 3D browser game (and mobile-friendly) built on Three.js, with procedural music, generated textures, and a primitive but honestly functional game loop.

Метод: как заставить агента работать «в одиночку» и всё же видеть прогрессThe method: getting an agent to work solo while still being able to watch it

Главная практическая находка статьи — не про игры, а про то, как удобно наблюдать за долгой автономной сессией Claude Code for web, у которой обычно нет способа быстро показать промежуточный результат. Willison создаёт на GitHub новый репозиторий, запускает сессию Claude Code (в приложении, на десктопе или на claude.ai/code) и с самого начала просит агента как можно быстрее закоммитить рабочий index.html. Затем в настройках репозитория (Settings → Pages) он включает «Deploy from a branch» и указывает ветку, которую создал агент (вида claude/3d-raccoon-heist-game-50n293). Дальше каждый пуш агента через ~30 секунд появляется на yourname.github.io/your-repo/ — можно следить за прогрессом с телефона, вообще не трогая код руками. The article's real practical payoff isn't about games — it's about watching a long autonomous Claude Code for web session that otherwise has no quick way to show intermediate progress. Willison creates a new GitHub repo, starts a Claude Code session (app, desktop, or claude.ai/code) and asks it up front to commit a working index.html as fast as possible. He then goes to the repo's Settings → Pages, picks "Deploy from a branch," and selects whatever branch the agent created (something like claude/3d-raccoon-heist-game-50n293). From then on, every push the agent makes shows up at yourname.github.io/your-repo/ within about 30 seconds — letting him watch progress from his phone without touching any code himself.

Промпт был написан на телефоне, в заметках, и намеренно закрывал агенту путь к диалогу: «работай самостоятельно — не спрашивай меня о дальнейших дизайнерских решениях», «коммить и пушь как можно чаще, чтобы я мог видеть прогресс», «веди notes.md и дополняй его при каждом коммите». Отдельный приём: Fable 5 получила ключ OpenAI API и была направлена использовать gpt-image-2 для текстур и арта — то есть модель одной компании намеренно подключили к API генерации изображений другой, чтобы закрыть пробел в собственных возможностях. По наблюдению Willison, Fable отлично формулирует промпты для генераторов изображений даже когда сама изображения не рисует. The prompt itself was typed on his phone, in the Notes app, and deliberately cut off any back-and-forth: "work independently — do not ask me to make any further design decisions," "commit and push as often as possible so I can preview your work," keep a notes.md and append to it with every commit. One specific trick: Fable 5 was handed an OpenAI API key and told to use gpt-image-2 for textures and art — deliberately wiring one company's model into another company's image-generation API to plug a capability gap. Willison notes that Fable is very good at prompting image generators even though it can't draw images itself.

Агент сам себя тестировал — и сам находил багиThe agent tested itself — and caught its own bugs

Не получив инструкций по тестированию, Fable 5 самостоятельно решила «прогнать дымовые тесты в предустановленном Chromium» через Playwright: делала скриншоты десктопной и мобильной раскладки и «разглядывала» их, обнаружив, например, что енот-игрок невидим на мобильной ширине экрана, и тут же это исправила. Позже похожим прогоном через Playwright она поймала два реальных бага перед сдачей: canvas рендерился в двойном размере на настоящих телефонах (десктопные тесты с DPR=1 это маскировали), и оверлей экрана победы перехватывал все тапы по кнопке «следующая ночь» из-за унаследованных на всё окно CSS-стилей. Оба бага были исправлены и закрыты регрессионными тестами до итогового отчёта агента о завершении работы. With no testing instructions given, Fable 5 decided on its own to "smoke-test in the pre-installed Chromium" via Playwright: it took screenshots at desktop and mobile widths and eyeballed them, catching (for instance) that the player raccoon was invisible at mobile width, and fixed it immediately. Later, a similar Playwright pass caught two real bugs before declaring the project done: the canvas was rendering at 2x size on real phones (desktop DPR-1 tests had masked this), and the win-screen overlay was silently swallowing every tap on the "next night" button because it inherited full-screen CSS from the title screen. Both were fixed and regression-tested before the agent's final completion report.

Вердикт: впечатляющая отправная точка, но не играThe verdict: an impressive starting point, not a game

Готовый результат — раскрадывающий двор еж-о́т, простите, енот, который собирает пончики, монеты и рыбу, уворачиваясь от патрульных с фонариками и (с третьей «ночи») собаки, идущей по запаху вне зависимости от прямой видимости. Willison честно называет игру посредственной: нет командной механики (два других енота — просто декорация), сложность растёт слабо, а после сбора всех предметов за ночь игроку буквально нечего делать до рассвета. Но как демонстрация возможностей одного промпта — это, по его оценке, действительно впечатляюще: полноценный 3D-рендер, процедурные персонажи и звук без единого аудиофайла, генерируемые текстуры без CDN-зависимостей. Общий вывод: почти все его эксперименты с «вайб-кодингом» игр разочаровывают именно в игровом дизайне — придумать, что делает игру увлекательной, остаётся человеческим навыком, — но проекты с играми всё равно остаются дешёвым и показательным способом прощупывать границы возможностей агентов. The finished result: a masked raccoon looting a yard for donuts, coins, gems and fish while dodging flashlight-wielding guards and, from night three, a dog that tracks by smell regardless of line of sight. Willison is blunt that the game itself is mediocre: there's no team mechanic (the other two raccoons are pure decoration), difficulty barely escalates, and once you've collected everything for the night there's nothing left to do before dawn. But as a demonstration of what a single prompt can produce, he calls it genuinely impressive: full 3D rendering, procedural characters and sound with zero audio files, generated textures with no CDN dependencies. His overall takeaway: nearly all of his game vibe-coding experiments disappoint specifically on game design — figuring out what makes a game actually fun remains a distinctly human skill — but game projects remain a cheap, revealing way to probe the edges of what agents can do.
