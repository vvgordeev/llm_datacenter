GitHub Octoverse 2026: агентная разработка в цифрах GitHub Octoverse 2026: agentic engineering by the numbers

Оригинал заметки ↗Original note ↗

Уиллисон ведёт репортаж прямо с конференции GitHub Universe (бесплатный билет он получил по программе GitHub Stars) и приводит цифры из годового отчёта Octoverse 2026, которые со сцены представил EVP GitHub Джей Парикх. Главный тезис заметки — то, насколько резко агентная разработка изменила форму всех трёх базовых графиков платформы: вместо плавного роста все три линии почти горизонтальны до середины 2025 года, а затем круто уходят вверх. Willison is reporting live from GitHub Universe (he got a free ticket through the GitHub Stars program) and relays figures from the Octoverse 2026 annual report, presented on stage by GitHub EVP Jay Parikh. The note's central point is how sharply agentic engineering has bent the shape of all three of the platform's core charts: instead of smooth growth, each line stays nearly flat until mid-2025 and then turns sharply upward.

Три графика: pull request'ы, коммиты, репозиторииThree charts: pull requests, commits, repositories

Число смёрженных pull request'ов в 2026 году утроилось менее чем за год и достигло 220 миллионов в месяц. Число коммитов выросло более чем втрое — до 7,38 миллиарда в месяц, причём основная часть этого роста пришлась на вторую половину года (на фотографии со сцены именно эта линия даёт самый крутой, почти вертикальный финальный скачок). Темп создания новых репозиториев удвоился за этот же год — до 30,3 миллиона в месяц. Уиллисон прямо называет это наглядным представлением влияния агентной разработки на GitHub: не постепенное улучшение инструментов, а структурный перелом в том, как быстро и как много кода пишется и публикуется. Merged pull requests in 2026 tripled in under a year to 220 million per month. Commits grew more than threefold, to 7.38 billion per month, with most of that increase concentrated in the second half of the year (in the on-stage photo, this is the line with the steepest, almost vertical final spike). The rate of new repository creation doubled over the same year, to 30.3 million per month. Willison calls this a stark representation of agentic engineering's impact on GitHub — not a gradual tooling improvement, but a structural break in how fast and how much code gets written and published.

Как считали «интероперабельность и реверс-инжиниринг»How "interoperability and reverse engineering" was measured

Отдельный интерес у Уиллисона вызывает методология отчёта: Octoverse 2026 впервые разбивает репозитории по отраслям и отдельно считает репозитории, связанные с «интероперабельностью или реверс-инжинирингом». По методологии GitHub, страновая принадлежность пушей в публичные репозитории уточняется с помощью LLM-классификации профиля пользователя (чтобы скорректировать погрешность от использования VPN), отраслевая категория каждого репозитория 2022–2026 годов присваивается через доученную мультиязычную embedding-модель по названию, описанию, темам и README, а сами репозитории по интероперабельности/реверс-инжинирингу отбираются по упоминанию в названии, описании, темах или README таких терминов, как «clean room implementation», «drop-in replacement» или «protocol re-implementation». Уиллисон приводит эти методологические детали без собственной оценки — как любопытный пример того, что сам инструментарий аналитики (LLM и embedding-модели) теперь используется для измерения последствий распространения этого же инструментария. Willison is particularly interested in the report's methodology: Octoverse 2026, for the first time, breaks repositories out by industry and separately counts repositories tied to "interoperability or reverse engineering." By GitHub's methodology, the country attribution of pushes to public repositories is refined using LLM classification of the user's profile (to correct for VPN-related bias), each repository created between 2022 and 2026 is sorted into an industry sector by a fine-tuned multilingual embedding model reading its name, description, topics, and README, and interoperability/reverse-engineering repositories are flagged by mentions in those same fields of terms like "clean room implementation," "drop-in replacement," or "protocol re-implementation." Willison presents these methodology details without much editorializing — as a notable example of the analysis tooling itself (LLMs and embedding models) now being used to measure the fallout of that same tooling's spread.
