Метод: фреймворк «четыре С»The method: the "Four Cs" framework

Центральная часть видео — фреймворк из четырёх составляющих [02:12]: Context (контекст) — вся история, знания и данные о конкретном человеке и его бизнесе, собранные в одном месте; Connections (связи) — то, как разрозненные факты и документы соединяются друг с другом в единый граф знаний, а не лежат изолированными файлами; Capabilities (возможности) — набор инструментов и навыков (skills), которые агент может вызывать для действия, а не только для ответа; Cadence (каденция, ритм) — регулярный цикл обновления и проверки системы, без которого она быстро устаревает. По мысли Херка, именно связка этих четырёх элементов, а не любой из них по отдельности, превращает обычный чат с моделью в персональную операционную систему. The video's centerpiece is a four-part framework [02:12]: Context — all the history, knowledge, and data about a specific person and their business gathered in one place; Connections — how scattered facts and documents link into a single knowledge graph rather than sitting as isolated files; Capabilities — the tools and skills the agent can invoke to act, not just to answer; Cadence — the regular cycle of updating and auditing the system, without which it quickly goes stale. Herk's point is that combining all four, not any one alone, is what turns an ordinary chat with a model into a personal operating system.

Онбординг системы и навык «grill-me»Onboarding the system, and the "grill-me" skill

Херк проходит через онбординг AIOS с нуля [08:40]: система задаёт вопросы о бизнесе, целях и рабочих процессах пользователя и постепенно выстраивает первоначальный контекст. Для углубления этого контекста он использует отдельный навык «grill-me» («допроси меня») [13:46] — агент целенаправленно засыпает пользователя уточняющими вопросами, чтобы вытащить неявные детали о его работе, которые тот сам не догадался бы сформулировать заранее. Herk walks through onboarding the AIOS from a blank state [08:40]: the system asks questions about the user's business, goals, and workflows and gradually builds up an initial context. To deepen that context further, he uses a separate "grill-me" skill [13:46] — the agent deliberately peppers the user with follow-up questions to surface implicit details about their work that they wouldn't have thought to state up front.

Владение данными: локальные файлы вместо привязки к вендоруData ownership: local files instead of vendor lock-in

Принципиальный выбор архитектуры, на котором Херк настаивает отдельно [18:35]: вся AIOS строится поверх обычных локальных файлов и папок, а не проприетарного формата памяти конкретного вендора. Это даёт две вещи — интеллектуальную собственность на собственные данные и свободу переключать модели и инструменты (Claude, Codex, любой другой агент) без переноса всей накопленной базы контекста в новый закрытый формат. A deliberate architectural choice Herk stresses on its own [18:35]: the whole AIOS is built on top of plain local files and folders, not a vendor-specific proprietary memory format. That buys two things — ownership of your own data, and the freedom to swap models and tools (Claude, Codex, any other agent) without migrating the whole accumulated context base into a new closed format.

ОграниченияLimitations

Построение такой системы требует заметных первоначальных инвестиций времени (сам онбординг и regular «grill-me»-сессии) и дисциплины по её поддержанию — Херк прямо говорит, что без регулярной каденции обновления AIOS теряет ценность так же быстро, как и любая заброшенная база знаний; метод также не даёт готовой гарантии приватности данных, если владелец сам решит подключить систему к облачным инструментам поверх локальных файлов. Building such a system takes a meaningful upfront time investment (the onboarding itself and regular "grill-me" sessions) and ongoing discipline to maintain it — Herk says outright that without a regular update cadence the AIOS loses value just as fast as any abandoned knowledge base; the method also offers no built-in privacy guarantee if the owner chooses to hook the system up to cloud tools on top of the local files.
