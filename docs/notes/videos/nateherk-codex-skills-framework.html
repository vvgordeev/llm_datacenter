Дальше видео разворачивает не список готовых скиллов, а метод их создания — шесть шагов, которые Херк демонстрирует на собственном скилле для написания статей под X (Twitter). Nate Herk, who runs a channel about AI automation, introduces the idea of a Codex skill with a pancake-recipe analogy [00:20]: it's a markdown file that documents, once, exactly how to run a repeatable process, so the agent executes it the same reliable way every time instead of re-interpreting the task from scratch. The video then unfolds not as a list of ready-made skills but as a method for building them — six steps, which Herk demonstrates on his own skill for writing articles for X (Twitter).

Шаги 1-2: результат в обратную сторону, один узкий триггерSteps 1-2: work backward from the output, one narrow trigger

Первый шаг — обратное проектирование: начать не с процесса, а с того, что вы считаете готовым, качественным результатом, и уже от него достраивать шаги, которые к нему приводят [01:55]. Второй шаг — гранулярность: у каждого скилла должна быть одна конкретная работа и одно чёткое условие запуска, а не попытка закрыть сразу несколько сценариев одним файлом [03:41]. По мысли Херка, именно узкие, предсказуемо запускаемые скиллы потом надёжно комбинируются друг с другом — тогда как скилл «на все случаи» превращается в набор нечётких инструкций, которые агент трактует по-разному от запуска к запуску. The first step is reverse engineering: start not from the process but from what you consider a finished, high-quality output, and work backward to the steps that produce it [01:55]. The second is granularity: every skill should do one specific job with one clear trigger, rather than trying to cover several scenarios in a single file [03:41]. Herk's point is that narrow, predictably-triggered skills chain together reliably later, whereas a catch-all skill collapses into vague instructions the agent interprets differently from one run to the next.

Шаги 3-4: уровень свободы и верификацияSteps 3-4: freedom level and verification

Третий шаг вводит понятие «уровня свободы»: нужно заранее решить, детерминированная перед вами задача (правила, которые можно расписать пошагово) или недетерминированная (требующая суждения) — от этого зависит, насколько жёсткими и подробными должны быть инструкции в скилле [06:28]. Для недетерминированных задач Херк советует не пытаться прописать всё заранее, а закладывать больше пространства для итеративной обратной связи. Четвёртый шаг — верификация: скилл должен включать отдельный цикл проверки результата на соответствие стандарту, зачастую силами второго ИИ-агента, а не полагаться на то, что первый прогон окажется правильным [09:06]. Это тот же принцип «доверяй, но проверяй», который делает скилл пригодным для повторного использования без ручного контроля. The third step introduces a "freedom level": decide upfront whether the task is deterministic (rules you can spell out step by step) or non-deterministic (judgment-based) — that decision drives how rigid and detailed the skill's instructions need to be [06:28]. For non-deterministic tasks, Herk's advice is not to try to specify everything upfront but to leave more room for iterative feedback. The fourth step is verification: a skill should include a separate check of its output against a standard, often run by a second AI agent, rather than trusting the first pass to be correct [09:06]. It's the same "trust but verify" principle that makes a skill safe to reuse without a human checking every run.

Шаги 5-6 и живая демонстрацияSteps 5-6 and a live demo

Пятый шаг, «спуск» («walk it down»), — как только скилл даёт нужное качество на мощной модели, его нужно систематически прогонять на всё более дешёвых моделях, пока не найдётся самая простая из них, ещё удерживающая планку качества [12:33]. Шестой — «метод велосипеда»: разработка скилла не одноразовая задача, а постоянный цикл обратной связи, как при обучении ребёнка езде на велосипеде — поддержку постепенно убирают, а исправления вносят по ходу дела. В демонстрации Херк на практике создаёт и тестирует скилл «X-статья» в Codex [15:35], а затем сравнивает результат его работы на разных моделях (Luna, Terra, Sol), наглядно показывая, как выглядит «спуск» на практике и на каком уровне модели скилл ещё держит нужное качество [20:01]. The fifth step, "walk it down," says that once a skill hits the desired quality on a capable model, you systematically test it on progressively cheaper models until you find the simplest one that still clears the bar [12:33]. The sixth, the "bike method," treats skill-building as an ongoing feedback loop rather than a one-time task — like teaching a kid to ride a bike, support is gradually removed and corrections happen along the way. In the demo, Herk builds and tests an "X article" skill in Codex live [15:35], then compares its output across different models (Luna, Terra, Sol), making concrete what "walking it down" looks like and at what model tier the skill still holds its quality bar [20:01].
