Дейв Эббелаар разбирает конкретный приём: как перенести кодинг-агентов (Claude Code, Codex) с ноутбука на виртуальный частный сервер (VPS), чтобы они продолжали работать, пока ноутбук закрыт [00:00]. Идея в том, что долгие агентные задачи — многошаговый рефакторинг, фоновые прогоны тестов, длительные исследовательские сессии — плохо совместимы с тем, что сессия обрывается при закрытии крышки лэптопа или потере Wi-Fi; постоянный облачный воркспейс снимает эту зависимость. Dave Ebbelaar walks through a specific technique: moving coding agents (Claude Code, Codex) off a laptop and onto a Virtual Private Server (VPS) so they keep running while the laptop is closed [00:00]. The idea is that long agentic tasks — multi-step refactors, background test runs, long research sessions — don't mix well with a session that dies when you close the lid or lose Wi-Fi; a persistent cloud workspace removes that dependency.

Herdr как мультиплексор терминалов для агентовHerdr as a terminal multiplexer for agents

Центральный инструмент — Herdr, который автор описывает как мультиплексор терминалов, спроектированный специально под ИИ-агентов (по сути, аналог tmux, но заточенный под агентные сессии): он позволяет запускать несколько агентов параллельно и сохраняет состояние каждой SSH-сессии между подключениями [00:39]. Автор показывает пошаговую настройку VPS на Hostinger — выбор тарифа, создание инстанса, первое подключение по SSH [02:37]. The central tool is Herdr, which the author describes as a terminal multiplexer purpose-built for AI agents (effectively a tmux analog tuned for agent sessions): it runs multiple agents in parallel and preserves each SSH session's state across reconnects [00:39]. He walks through setting up a VPS on Hostinger step by step — picking a plan, spinning up the instance, the first SSH connection [02:37].

Метод защиты: от пароля root до файрвола по белому спискуThe security method: from a root password to a firewall allowlist

Заметная часть видео посвящена именно безопасности облачного рабочего места, а не самому Herdr. Эббелаар настаивает на конкретной последовательности шагов: сначала — надёжный пароль root и переход на аутентификацию по SSH-ключам вместо пароля [05:40], затем — настройка файрвола так, чтобы входящий трафик принимался только с разрешённых («белый список») IP-адресов [12:49]. Логика метода: сервер, на котором агент может выполнять произвольный код и имеет доступ к приватным репозиториям, — это по сути ещё одна точка входа в инфраструктуру разработчика, и её нельзя оставлять с настройками по умолчанию. A substantial chunk of the video is about securing the cloud workspace itself, not about Herdr per se. Ebbelaar insists on a specific sequence: first, a strong root password and a switch to SSH-key authentication instead of password login [05:40], then a firewall configured to accept inbound traffic only from an allowlisted set of IPs [12:49]. The logic of the method: a server where an agent can execute arbitrary code and reach private repos is effectively another entry point into a developer's infrastructure, and it can't be left on default settings.

Next comes installing and authenticating GitHub CLI, Claude Code, and Codex directly on the server [15:50], followed by connecting a local editor (Cursor or VS Code) to the remote Herdr instance over SSH, so you can work with code, git history, and agents through a familiar GUI rather than a bare terminal [23:23]. The video closes with practical day-to-day maintenance tips for a server like this [25:07]. A limit of the approach that follows from the video itself: it assumes a developer willing to take on their own VPS administration (updates, monitoring, backups) — this is self-managed infrastructure, not a managed service.
