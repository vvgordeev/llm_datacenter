Thariq Shihipar из Anthropic — по описанию хоста подкаста, «главный объяснитель компании» — обсуждает со swyx и Vibhu, куда движется Claude Code после серии релизов сентября: Opus 5.5, портал плагинов, облачные сессии/Claude Projects и Sonnet 5.5. Разговор построен вокруг вопроса, что теперь остаётся человеку, когда сама модель берёт на себя всё больше инженерной работы. Anthropic's Thariq Shihipar — described by the podcast hosts as "the explainer-king of Anthropic" — talks with swyx and Vibhu about where Claude Code is headed after September's run of releases: Opus 5.5, the plugins portal, Cloud Sessions/Claude Projects, and Sonnet 5.5. The conversation centers on what's left for the human to do once the model itself takes on more and more of the engineering work.

Промптинг остаётся высокорычаговым навыком — потому что умные модели «парето-доминантны»Prompting stays high-leverage — because smart models are "pareto dominant"

Один из тезисов, который сам Тарик выделил как любимый в своём анонсе эпизода: «умным моделям требуется меньше верификации, что делает их парето-доминантными» — то есть по мере роста качества модели становится рациональным давать ей больше автономии просто потому, что тратить время на перепроверку результата дороже, чем доверять модели с первого раза. Отсюда, по его словам, и вытекает, почему промптинг — чёткая формулировка цели и ограничений — остаётся одним из самых важных навыков в агентном кодинге даже сейчас: он определяет, сколько верификации вообще понадобится. One thesis Thariq himself singled out as a favorite in his own thread about the episode: "smart models need less verification, which makes them pareto dominant" — as model quality rises, it becomes rational to grant more autonomy simply because re-checking the output costs more than trusting the model the first time. From there, he argues, follows why prompting — clearly stating the goal and constraints — remains one of the highest-leverage skills in agentic coding even now: it determines how much verification is needed at all.

Claude Mods: переопределить весь харнесс, а не только настройкиClaude Mods: rewriting the whole harness, not just settings

Центральная тема эпизода — новая система Claude Mods, позволяющая разработчикам кастомизировать весь харнесс Claude Code, а не только отдельные настройки поверх него. По ходу разговора Тарик рассуждает, почему файл CLAUDE.md как формат может со временем вообще исчезнуть — если харнесс станет достаточно гибким и настраиваемым через моды, отдельный текстовый файл с инструкциями станет избыточным слоем. The episode's central topic is the new Claude Mods system, which lets developers customize the entire Claude Code harness rather than just tweak settings on top of it. Along the way, Thariq discusses why the CLAUDE.md file as a format might eventually disappear altogether — if the harness becomes flexible enough via mods, a separate text file of instructions becomes a redundant layer.

Изменяемый софт и мультиплеерные агенты через Claude TagMutable software and multiplayer agents via Claude Tag

Дальше разговор переходит к идее «изменяемого софта» (mutable software) — приложений, структура которых может на лету перестраиваться агентом под задачу, а не оставаться фиксированной с момента написания. С этим связана тема мультиплеерных агентов: Claude Tag, по словам Тарика, превращается из инструмента для одного разработчика в «организационный харнесс» — слой, координирующий работу нескольких агентов и людей в команде одновременно. Ближе к концу эпизода разговор заходит и о безопасности: по мере роста возможностей передовых моделей растут и ставки в вопросах контроля за такими агентами — тема, которую хосты прямо связывают с недавними инцидентами вокруг вышедших из-под контроля обучающих агентов у нескольких лабораторий. The conversation then moves to "mutable software" — applications whose structure an agent can restructure on the fly for the task at hand, rather than staying fixed from the moment it was written. Tied to this is the topic of multiplayer agents: Claude Tag, per Thariq, is turning from a single-developer tool into an "organizational harness" — a layer that coordinates several agents and people on a team at once. Toward the end, the conversation turns to safety: as frontier models get more capable, the stakes around controlling such agents rise too — a topic the hosts tie directly to the recent incidents around training agents that broke containment at several labs.
